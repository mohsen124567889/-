# رِفاء — نظام طلب وتوصيل مياه الشرب (نسخة Firebase)

مشروع ويب عربي متجاوب، يتكون من واجهة العميل ولوحة الإدارة وواجهة السائق حسب دور الحساب، ويستخدم Firebase Authentication وCloud Firestore مباشرة.

## ما يعمل بعد ربط Firebase ونشر القواعد
- إنشاء حساب عميل بالبريد وكلمة المرور وتسجيل الدخول.
- إنشاء طلبات فعلية في Firestore.
- تحديث الطلبات لحظياً للعميل والإدارة والسائق.
- إدارة المنتجات (إضافة من لوحة الإدارة).
- إسناد الطلب إلى سائق.
- تحديث حالة الطلب من الإدارة والسائق.
- حفظ صلاحيات الأدوار في مستند المستخدم.
- قواعد Firestore وStorage مرفقة.

## مهم جداً قبل التشغيل
لا يمكن لأي نسخة أن تتصل بمشروع Firebase جديد قبل أن تنشئه الشركة وتضيف إعدادات Web App الخاصة به. لا توجد مفاتيح Firebase أو حسابات فعلية مضمنة في هذا الملف.

## 1) إنشاء مشروع Firebase
1. افتح https://console.firebase.google.com/ وأنشئ مشروعاً باسم Refaa.
2. من Project settings أضف تطبيق Web.
3. انسخ كائن إعدادات Firebase والصقه في `public/firebase-config.js` مكان القيم التجريبية.
4. من Authentication → Sign-in method فعّل Email/Password.
5. من Firestore Database أنشئ قاعدة بيانات.
6. من Storage أنشئ مساحة تخزين (اختياري حالياً للصور).
7. من Firestore → Rules انشر محتوى `firestore.rules`.
8. من Storage → Rules انشر محتوى `storage.rules`.

## 2) إنشاء أول مدير (خطوة يدوية آمنة)
1. شغّل الموقع وأنشئ حساباً عادياً من واجهة إنشاء الحساب.
2. افتح Firebase Console → Firestore Database → `users`.
3. افتح مستند المستخدم الذي يحمل UID الخاص بحسابك.
4. غيّر الحقل `role` من `customer` إلى `admin`.
5. سجّل الخروج ثم الدخول مجدداً. ستظهر لوحة الإدارة.

لا تجعل إنشاء دور admin متاحاً من واجهة التسجيل العامة. القواعد تمنع المستخدم من ترقية نفسه.

## 3) إنشاء حساب سائق
1. أنشئ حساباً عادياً للسائق من صفحة التسجيل.
2. من Firebase Console افتح مستند `users/{uid}` لهذا الحساب.
3. غيّر `role` إلى `driver`.
4. يسند المدير الطلبات لهذا الحساب من لوحة الإدارة.

## 4) نشره على GitHub Pages
- ارفع محتويات المجلد إلى مستودع GitHub.
- Settings → Pages → Deploy from a branch.
- اختر `main` ومجلد `/ (root)` إذا وضعت الملفات في جذر المستودع.
- إذا أبقيت مجلد `public` كما هو، يفضّل استخدام Firebase Hosting أو نقل محتوياته إلى جذر مستودع النشر. الأسهل: انسخ محتويات `public/` إلى جذر مستودع منفصل.
- GitHub Pages يدعم الواجهة فقط؛ لا ينشر قواعد Firestore. انشر القواعد من Firebase Console أو Firebase CLI.

## 5) نشر قواعد Firebase عبر CLI (اختياري)
ثبت Firebase CLI على جهاز كمبيوتر:
```bash
npm install -g firebase-tools
firebase login
firebase use --add
firebase deploy --only firestore:rules,firestore:indexes,storage
firebase deploy --only hosting
```
ملف `firebase.json` يضبط مجلد Hosting على `public`.

## حدود النسخة الحالية — لا تعتبرها مكتملة تجارياً بعد
- تسجيل الدخول بالبريد وكلمة المرور، وليس OTP بالجوال.
- الدفع عند الاستلام فقط. لا يوجد دفع إلكتروني.
- رسوم التوصيل مضبوطة حالياً على صفر؛ يجب تحديدها وفق سياسة الشركة.
- لا يوجد تتبع GPS حي للسائق أو خرائط.
- لا يوجد إرسال SMS/WhatsApp أو إشعارات Push.
- صور المنتجات ورفعها تحتاج استكمال واجهة Storage.
- لا يوجد نظام مخزون/خصومات/فواتير ضريبية/اشتراكات دورية متكامل.
- قواعد الأمان تحتاج مراجعة واختبار قبل تشغيل بيانات عملاء حقيقية، خصوصاً إجراءات الإدارة وحالات الطلب.
- GitHub Pages مناسب للواجهة فقط، وFirebase هو الخلفية وقاعدة البيانات.

## هيكل المشروع
- `public/index.html` واجهات العميل والإدارة والسائق.
- `public/firebase-config.js` إعدادات تطبيق Firebase.
- `public/manifest.webmanifest` إعدادات PWA.
- `public/sw.js` التخزين المؤقت الأساسي.
- `firestore.rules` صلاحيات قاعدة البيانات.
- `storage.rules` صلاحيات التخزين.
- `firebase.json` إعداد Hosting.
